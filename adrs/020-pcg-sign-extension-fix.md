# ADR-020: PCG実装の符号拡張バグを修正し参照アルゴリズムに一致させる

**Status**: Proposed

## Context

ADR-010 で採用した PCG（`rng.mbt` の `pcg_next32`）が、参照実装 PCG XSH-RR 64/32（いわゆる pcg32）と一致しないことがコードレビューで判明した。

原因は MoonBit の `Int64` に対する `>>` が算術右シフト（符号ビット維持）であること。`(old >> 18) ^ old` の `old >> 18` が負の状態（全状態の約50%）で符号拡張し、拡張された上位ビットが XOR 経由で抽出窓（`>> 27` 後の下位32ビット）に混入する。その結果、出力の上位13ビットが状態の符号ビットと XOR された「未解析の変種アルゴリズム」になっていた。

独立に書いたビット単位シミュレーションで検証したところ、20,000 状態中 9,899 状態（全て bit63=1 の状態）で参照実装と出力が不一致だった。回転量 rot（bits 59-63）とも相関するため、PCG が持つ統計的保証は失われている。

また、コード中のコメントは「PCG-64」と表記していたが、これは 64bit 出力の別アルゴリズムの名前であり誤記（実装しているのは 64bit 状態 / 32bit 出力の PCG XSH-RR 64/32）。

## Decision

**`old >> 18` の結果を46ビットマスク（`& 0x3FFF_FFFF_FFFFL`）で論理シフト相当に補正し、参照 PCG XSH-RR 64/32 と出力を一致させる。**

- `>> 27` 側は補正不要（符号拡張はビット37-63にのみ影響し、`.to_int()` が取る下位32ビットには到達しない）
- 回転量 `(old >> 59) & 31` も補正不要（`& 31` がビット0-4のみを残す）
- コメントの「PCG-64」表記を「PCG XSH-RR 64/32 (pcg32)」に訂正
- 参照実装（BigInt による独立実装）で計算した期待値をホワイトボックステストに固定し、将来の実装ドリフトを検出できるようにする

本 ADR は **ADR-010 の改訂**（採用アルゴリズム自体は変更なし、実装バグの修正）。

## Consequences

- 乱数出力が変わるため、GA の進化系列は修正前と一致しない（アルゴリズム上の品質は参照 PCG の保証に回復する）
- 乱数品質を参照値と突き合わせる保守者が「実装が壊れている」と誤診するリスクが消える
- 固定シードの期待値テストにより、以後のシフト/マスク回りのリグレッションは即検出される
